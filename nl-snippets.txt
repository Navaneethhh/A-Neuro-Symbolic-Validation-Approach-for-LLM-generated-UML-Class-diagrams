A Library manages multiple Book Items and registered Patrons. Each Book has a title, ISBN, and publication year, and can have multiple physical Book Items with individual barcode IDs and status. Patrons have a member ID, name, and membership date, and can borrow up to five Book Items simultaneously through Loan transactions. Each Loan records the checkout date, due date, and return date. A Librarian processes loans and manages book inventory.

A modern academic library supports digital media loans and reservation queues. DigitalResource (with attributes resourceId, title, licenseExpiry, and fileSize) can be reserved by Students and Faculty. If a resource or physical copy is unavailable, a Patron places a Reservation with a reservationDate and priorityStatus. The system tracks notification logs and automatically expires unfulfilled reservations after seven days.

A library billing subsystem manages overdue books. A Patron who fails to return a BookItem before the Loan dueDate incurs an OverdueFine. The fine entity contains fineId, calculationDate, amountPerDay, totalAmount, and paidStatus. A Payment transaction (paymentId, amountPaid, transactionDate, paymentMethod) settles one or more fines. Librarians can issue waivers or suspend borrowing privileges if unpaid fines exceed a set threshold.

A regional public library network consists of multiple Branch libraries (branchId, branchName, location). A CentralCatalog coordinates inter-library loan transfers between branches. When a Patron requests a book located at another branch, an InterLibraryTransfer request is created containing transferId, dispatchDate, arrivalDate, and shippingStatus. Librarians at the sending and receiving branches update transfer milestones.

A research library maintains an archival indexing system. An Author has authorId, fullName, and nationality, and can write multiple Books. Each Book belongs to one primary SubjectCategory (categoryCode, categoryName, deweyDecimalNumber) and may reference parent or sub-categories. RareManuscripts inherit from Book with additional attributes preservationCondition, restorationHistory, and restrictedAccessLevel.

An EHR subsystem manages patient records where a Patient (patientId, legalName, dateOfBirth, bloodGroup) is assigned a PrimaryCarePhysician (Doctor). A Doctor has employeeId, fullName, specialization, and licenseNumber. Each Patient has an ongoing MedicalRecord containing multiple ClinicalNotes and allergy records. Doctors create and append diagnostic reports to the patient's record during consultations.

A hospital inpatient management system manages Wards (wardNumber, department, capacity) and Beds (bedId, roomNumber, isOccupied). When a Patient is admitted, an Admission record is generated containing admissionDate, dischargeDate, admittingDoctor, and diagnosisSummary. Patients are assigned to exactly one Bed at any given time, and Nurses (staffId, shiftTiming) monitor assigned beds across wards.

A clinical prescription module connects Doctors, Patients, and the Pharmacy. During an encounter, a Doctor writes a Prescription containing prescriptionDate and dosageInstructions. Each Prescription contains multiple PrescriptionItems referencing specific Medications (code, brandName, genericFormula, unitStrength). A Pharmacist dispenses the medications and creates a DispensationLog with timestamp and verificationSignoff.

An outpatient clinic appointment scheduler manages patient visits. A Patient schedules an Appointment with a Doctor specifying appointmentId, scheduledTime, appointmentType, and status (Booked, Completed, Cancelled). Prior to the doctor consultation, a TriageNurse records vital signs in a VitalSignsSheet (systolicBP, diastolicBP, heartRate, temperature, pulseOximetry) associated with the appointment.

A hospital surgical unit coordinates Operation Theatres (theatreId, roomLocation, sterileStatus). A SurgeryProcedure (procedureCode, procedureName, estimatedDuration) is scheduled in an Operation Theatre for a Patient. A dedicated SurgicalTeam is assembled for each operation, comprising a LeadSurgeon, Anesthesiologist, and ScrubNurses, each with designated surgical roles and checklist verifications.

An online retail platform allows registered Customers (customerId, email, shippingAddress) to maintain an active ShoppingCart. The cart contains multiple CartItems, each referencing a Product (productId, name, unitPrice, stockQuantity) and selected quantity. When checking out, the cart is converted into an Order (orderId, orderDate, orderStatus, totalAmount) with distinct OrderLineItems.

A multi-vendor e-commerce platform hosts multiple Vendors (vendorId, businessName, rating, taxId). Vendors list Products organized under a hierarchical ProductCategory (categoryId, categoryName, parentCategory). Vendors manage their own InventoryStock levels and product pricing. Customers submit Reviews (reviewId, ratingScore, commentText, reviewDate) for purchased Products.

An e-commerce payment settlement system handles transactions. An Order initiates a Payment transaction (paymentId, amount, transactionTimestamp, paymentStatus). The system supports multiple payment methods including CreditCardPayment (cardNumber, cardHolder, expiryDate) and DigitalWalletPayment (walletProvider, userHandle). Upon successful transaction clearance, the system issues an Invoice containing invoiceNumber, taxAmount, and billingDetails.

A logistics subsystem handles order fulfillment and shipping. Once an Order is packed, a Shipment entity is created (trackingNumber, carrierName, dispatchDate, estimatedDeliveryDate). A Shipment consists of multiple TrackingCheckpoints (timestamp, facilityLocation, eventDescription, updateStatus). CourierAgents (agentId, contactNumber, assignedVehicle) update delivery status upon handover to the customer.

An e-commerce customer retention module manages discounts and loyalty rewards. A Customer earns LoyaltyPoints (balance, tierLevel) from qualifying orders. Customers can apply CouponCodes (code, discountPercentage, minimumOrderValue, validUntil) to an Order during checkout. The system validates whether coupon terms apply and recalculates final order discounts and point accruals.
